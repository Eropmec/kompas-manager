# Менеджер проектов и библиотек для КОМПАС-3D

Программа для работы с проектами КОМПАС-3D v24: обозначения по схемам и переобозначение, библиотека типовых элементов, импорт таблиц из PDF.

## Где взять exe

Каждое изменение в ветке `main` собирается автоматически. Готовые файлы лежат в [Releases → последняя сборка](../../releases/latest):

- **KompasManager.exe** — менеджер проектов;
- **KompasProto.exe** — прототип, на котором проверялся Kompas API.

Python ставить не нужно, нужен установленный КОМПАС-3D v24. Exe не подписан, поэтому Windows при первом запуске может показать предупреждение SmartScreen: «Подробнее» → «Выполнить в любом случае».

## Менеджер проектов (версия 0.2)

Готовы модуль «Проект» и переобозначение.

### Переобозначение

1. **Схема.** «Обозначения → Схема обозначения…»: выбери схему из библиотеки и укажи код проекта. Схема — шаблон вида `{код}.{сборка:3}.{деталь:2}`: головная сборка АБВГ.000.00, подсборки АБВГ.001.00, АБВГ.002.00…, детали в подсборке АБВГ.001.01… Подсборки любого уровня нумеруются в одном поле. Библиотека схем общая для всех проектов («Библиотека схем…»), настройки проекта хранятся в файле `.kompas_manager.json` в папке проекта.
2. **Изменения.** Все изменения сначала только показываются в дереве синим и не пишутся в файлы:
   - «Применить схему» рассчитывает обозначения всех элементов по дереву;
   - двойной щелчок по обозначению или наименованию — правка вручную;
   - «Найти и заменить» (Ctrl+H) — массовая замена в наименованиях или обозначениях, во всём проекте или в выделенной сборке;
   - правая кнопка мыши: закрепить номер элемента (автонумерация его пропускает), исключить из нумерации (стандартные и покупные изделия), отменить изменение.
3. **Переобозначить** (Ctrl+Enter). Окно со списком «было → стало» по всем затронутым файлам: моделям, их чертежам и спецификациям, а также документам, где обновятся ссылки. При ошибках (дубли обозначений, занятые имена файлов) выполнить нельзя.
4. **Выполнение.** Все затронутые файлы копируются в `_backup/<дата_время>`. Затем через Kompas API: модели копируются под новыми именами и получают новые свойства, в сборках заменяются компоненты, в чертежах — источники видов и штамп, в спецификациях — связанные документы и штамп. Старые файлы удаляются, только если всё прошло без ошибок.
5. **Откат.** «Обозначения → Откатить последнее переобозначение» возвращает файлы из резервной копии.

Обозначение в штампе чертежа и спецификации = обозначение модели + код документа, если он был («АБВГ.000.00 СБ»). Имя файла — «Обозначение - Наименование» по штампу.

### Проект

**Открытие проекта.** «Файл → Открыть папку проекта». Программа читает через Kompas API все модели, чертежи и спецификации в папке и вложенных папках. Папки `_old` и `_backup` пропускаются. КОМПАС работает в фоне без окна. Если КОМПАС уже открыт, используется он, а документы, открытые в нём, не закрываются.

**Кэш.** Прочитанное запоминается. При следующем открытии или по «Обновить» (F5) читаются только изменённые файлы. Если ничего не менялось, КОМПАС не запускается вовсе. «Проект → Перечитать все файлы» читает всё заново.

**Дерево проекта.** Головные сборки, а в них подсборки и детали в порядке сборки. Для каждой строки: обозначение, наименование, тип, количество вхождений, связанные чертежи и спецификации, файл и состояние. Отдельно показаны детали вне сборок и документы без модели. Фильтр ищет по любому столбцу.

**Действия** (правая кнопка мыши): открыть в КОМПАСе (или двойной щелчок), открыть чертёж или спецификацию модели, показать в проводнике, копировать обозначение.

**Проверки:**

| Уровень | Что проверяется |
| --- | --- |
| Ошибка | битая ссылка (файл не найден); одно обозначение у нескольких файлов |
| Предупреждение | ссылка за пределы папки проекта; нет обозначения или наименования; имя файла не по шаблону «Обозначение - Наименование»; обозначение в штампе чертежа не совпадает с моделью; файл прочитан не полностью |
| Замечание | деталь без чертежа; сборка без спецификации; деталь не входит в сборки; чертёж без ассоциативных видов |

Двойной щелчок по проблеме показывает файл в дереве.

## Прототип

Папка `proto/` — прототип, на котором проверено, что Kompas API умеет всё, на чём держится переобозначение: запись свойств, перепривязка компонентов и видов, обновление штампа, сохранение под новым именем. Порядок проверки описан в истории проекта; прототип оставлен для повторных проверок API.

## Разработка

```
pip install -r requirements.txt pytest
python -m pytest tests
python run_manager.py
```

Структура:

- `kompas_manager/core/` — модель проекта, проверки, схемы и нумерация, план переобозначения, резервная копия, кэш. Не зависит от КОМПАСа, покрыто тестами.
- `kompas_manager/renamer.py` — выполнение переобозначения.
- `kompas_manager/kompas_api.py` — все вызовы Kompas API.
- `kompas_manager/scanner.py` — чтение папки проекта.
- `kompas_manager/ui/` — интерфейс на PySide6.
