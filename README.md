# Менеджер проектов и библиотек для КОМПАС-3D

Программа для работы с проектами КОМПАС-3D v24: обозначения по схемам и переобозначение, библиотека типовых элементов, импорт таблиц из PDF.

## Где взять exe

Каждое изменение в ветке `main` собирается автоматически. Готовые файлы лежат в [Releases → последняя сборка](../../releases/latest):

- **KompasManager.exe** — менеджер проектов;
- **KompasProto.exe** — прототип, на котором проверялся Kompas API.

Python ставить не нужно, нужен установленный КОМПАС-3D v24. Exe не подписан, поэтому Windows при первом запуске может показать предупреждение SmartScreen: «Подробнее» → «Выполнить в любом случае».

## Менеджер проектов (версия 0.8)

Готовы разделы с проектами, создание и правка структуры, версии узлов, перенос узлов, модуль «Проект», переобозначение и библиотека.

### Окно: разделы | изделие | источник

Справа — источник с вкладками «Изделия» (разделы + состав выбранного изделия) и «Библиотека». Выбранный элемент вставляется в выделенную сборку текущего изделия: узлы других изделий копируются целиком и отвязываются от исходных файлов (включая их библиотечные файлы), по выбору сразу нумеруются по схеме; библиотечные элементы копируются на уровень сборки и вставляются в неё, один файл на типоразмер. Встраивать изделия и узлы можно и перетаскиванием на сборку в дереве изделия (из разделов, из источника, внутри самого изделия), и через Ctrl+C / Ctrl+V; внутри одного изделия — ещё одним вхождением того же файла или независимой копией. «Создать уровень выше» — новая головная сборка над изделием без его изменения. «Проект → Сделать изделие автономным» и «Архивировать изделие» — для передачи проекта одной папкой (архив без _versions, _backup, _old).

Подробно — [docs/Руководство.md](docs/Руководство.md).

### Разделы

Слева — разделы: каждый раздел — путь к папке с проектами («Разделы…» — добавить папку, переименовать, удалить, изменить порядок). Разделы раскрываются плюсиком: заказчик → проект → изделие. Изделие (папка с файлами КОМПАСа) выделено жирным и открывается щелчком. Правая кнопка мыши:

- **Новое изделие (структура)…** (также Ctrl+N): дерево сборок и деталей с количеством, обозначения по схеме считаются сразу; «Создать файлы» создаёт модели (пустые или из шаблонов «Сервис → Настройки»), задаёт обозначения и наименования, вставляет компоненты и открывает изделие;
- **Новая папка, Переименовать, Обновить**;
- **Копировать / Вставить папку**: обычное копирование; после вставки программа проверяет ссылки копии и перепривязывает те, что вели в оригинал.

### Правка готовой сборки

В дереве изделия, правая кнопка мыши:

- **Добавить детали и сборки…** (на сборке): тот же редактор структуры; новые элементы получают следующие свободные номера после занятых, создаются и вставляются в сборку;
- **Удалить из сборки…** (Del, можно несколько выделенных): удаляет все вхождения из сборки-родителя; по выбору удаляются и файлы узла (модели, чертежи, спецификации), которые больше нигде в изделии не используются. Всё затронутое предварительно копируется в `_backup`.

**Ctrl+Z** («Правка → Отменить») отменяет последние действия этого сеанса (до 20) — файлы возвращаются из `_backup`.

### Версии узлов

**Версии узла…** (на сборке или детали): «Сохранить текущую версию» упаковывает узел со всем составом, чертежами и спецификациями в zip в папке `_versions` изделия, с комментарием. «Восстановить выбранную» сначала сохраняет текущее состояние как версию, затем распаковывает выбранную на свои места; если у текущего узла другой головной файл, родительские сборки перепривязываются на восстановленный. Файлы текущего узла, которых нет в версии, по выбору убираются в `_old`.

### Перенос узлов между изделиями

В дереве изделия правая кнопка на сборке или детали → «Копировать узел для другого проекта». Затем в другом изделии на сборке → «Вставить узел в эту сборку». Копируются модели узла, их чертежи и спецификации (библиотечные файлы — нет), ссылки внутри копий перепривязываются, узел вставляется компонентом. Пронумеровать узел по схеме нового изделия — «Применить схему».

### Библиотека

Вкладка «Библиотека» показывает папку библиотеки с подпапками по типам изделий. Элемент — модель КОМПАСа с внешними переменными.

- **Паспорт элемента** хранится рядом с моделью в файле `<модель>.kmlib.json`: тип (стандартное, по типу стандартного, покупное изделие, деталь), шаблоны обозначения и наименования из переменных (`BTEL.D{D}S{s}`, `Днище эллиптическое {ISP}-{D}-{s}`), таблица типоразмеров `.xlsx` (первая строка — имена переменных) и снимок переменных модели.
- **Вставка в проект**: выбираешь строку таблицы или вводишь значения вручную и папку проекта. Программа копирует модель в проект, записывает значения в переменные копии, перестраивает её, задаёт обозначение и наименование по шаблонам и называет файл «Обозначение - Наименование». Чертёж по копии строится с этими размерами, библиотечный оригинал не меняется. Если такой типоразмер уже есть в проекте, используется существующий файл. Путь к копии копируется в буфер обмена, чтобы добавить компонент в сборку в КОМПАСе.
- **Вынос вхождений** (правая кнопка на сборке в дереве проекта): вхождения, у которых переменные изменены прямо в сборке, выносятся в отдельные файлы с этими значениями, компоненты перепривязываются. Одинаковые наборы значений — один файл. Сборка перед изменением копируется в `_backup`.

### Переобозначение

1. **Схема.** «Обозначения → Схема обозначения…»: выбери схему из библиотеки и укажи код проекта. Схема — шаблон вида `{код}.{сборка:3}.{деталь:2}`: головная сборка АБВГ.000.00, подсборки АБВГ.001.00, АБВГ.002.00…, детали в подсборке АБВГ.001.01… Подсборки любого уровня нумеруются в одном поле. Библиотека схем общая для всех проектов («Библиотека схем…»), настройки проекта хранятся в файле `.kompas_manager.json` в папке проекта.
2. **Изменения.** Все изменения сначала только показываются в дереве синим и не пишутся в файлы:
   - «Применить схему» рассчитывает обозначения всех элементов по дереву;
   - двойной щелчок по обозначению или наименованию — правка вручную;
   - «Найти и заменить» (Ctrl+H) — массовая замена в наименованиях или обозначениях, во всём проекте или в выделенной сборке;
   - правая кнопка мыши: закрепить номер элемента (автонумерация его пропускает), исключить из нумерации (стандартные и покупные изделия), отменить изменение.
3. **Переобозначить** (Ctrl+Enter). Окно со списком «было → стало» по всем затронутым файлам: моделям, их чертежам и спецификациям, а также документам, где обновятся ссылки. При ошибках (дубли обозначений, занятые имена файлов) выполнить нельзя.
4. **Выполнение.** Все затронутые файлы копируются в `_backup/<дата_время>`. Затем через Kompas API: модели копируются под новыми именами и получают новые свойства, в сборках заменяются компоненты, в чертежах — источники видов и штамп, в спецификациях — связанные документы и штамп. Старые файлы удаляются, только если всё прошло без ошибок.
5. **Откат.** «Обозначения → Откатить последнее переобозначение» возвращает файлы из резервной копии.

Обозначение в штампе чертежа и спецификации = обозначение модели + код документа, если он был («АБВГ.000.00 СБ»). Имя файла — «Обозначение - Наименование» по штампу.

### Проект

**Открытие проекта.** «Файл → Открыть папку проекта». Программа читает через Kompas API все модели, чертежи и спецификации в папке и вложенных папках. Папки `_old` и `_backup` пропускаются. КОМПАС работает в фоне без окна. Если КОМПАС уже открыт, используется он, а документы, открытые в нём, не закрываются.

**Кэш.** Прочитанное запоминается. При следующем открытии или по «Обновить» (F5) читаются только изменённые файлы. Если ничего не менялось, КОМПАС не запускается вовсе. «Проект → Перечитать все файлы» читает всё заново.

**Дерево проекта.** Головные сборки, а в них подсборки и детали в порядке сборки. Для каждой строки: обозначение, наименование, тип, количество вхождений, связанные чертежи и спецификации, файл и состояние. Отдельно показаны детали вне сборок и документы без модели. Фильтр ищет по любому столбцу.

**Действия** (правая кнопка мыши): открыть в КОМПАСе (или двойной щелчок), открыть чертёж или спецификацию модели, показать в проводнике, копировать обозначение.

**Проверки:**

| Уровень | Что проверяется |
| --- | --- |
| Ошибка | битая ссылка (файл не найден); одно обозначение у нескольких файлов |
| Предупреждение | ссылка за пределы папки проекта; нет обозначения или наименования; имя файла не по шаблону «Обозначение - Наименование»; обозначение в штампе чертежа не совпадает с моделью; файл прочитан не полностью |
| Замечание | деталь без чертежа; сборка без спецификации; деталь не входит в сборки; чертёж без ассоциативных видов |

Двойной щелчок по проблеме показывает файл в дереве.

## Прототип

Папка `proto/` — прототип, на котором проверено, что Kompas API умеет всё, на чём держится переобозначение: запись свойств, перепривязка компонентов и видов, обновление штампа, сохранение под новым именем. Порядок проверки описан в истории проекта; прототип оставлен для повторных проверок API.

## Разработка

```
pip install -r requirements.txt pytest
python -m pytest tests
python run_manager.py
```

Структура:

- `kompas_manager/core/` — модель проекта, проверки, схемы и нумерация, план переобозначения, резервная копия, кэш. Не зависит от КОМПАСа, покрыто тестами.
- `kompas_manager/renamer.py` — выполнение переобозначения.
- `kompas_manager/kompas_api.py` — все вызовы Kompas API.
- `kompas_manager/scanner.py` — чтение папки проекта.
- `kompas_manager/ui/` — интерфейс на PySide6.
